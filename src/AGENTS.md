# Application and domain rules

These rules were moved verbatim from root guidance. They govern source changes and scripts exercising the corresponding flows.

- Xero calls and configured-state checks use the explicitly selected connector credential consistently, never a fallback connection; organisation routing remains fail-closed and TEST-only Demo isolation is preserved. Why: switching Xero accounts must not silently retain the old books.
- Document early recovery owns module error/rejection events; the router handles preload/route catches and cache-busts reloads. Why: competing refresh handlers can interrupt startup and leave stale tabs blank.
- Insulation tap answers use a pure route resolver and an immutable website-answer overlay saved by the `save_owner_insulation_details` RPC (live); preview hosts save only qa_test jobs, the published site saves real website owners, and answering the questions lets photo owners save their spot. Why: preview must not mutate real owners, but owners must be able to save.
- Usual electrician settings use business-scoped append-only config events; Mitti-only electrician/commercial facts use job audit snapshots and quote-specific electrical guards. Why: editable nominations and the new formula need history without altering legacy payer rules or approved partner rates.
- Office saved headlines share campaign cache. Office review count/paging shares one SELECT-only photos/exception predicate excluding offers; Removed is hidden, history retained; 0216 preserved. Why: exact totals, no duplicated piles or customer changes.
- Save My Spot reminders use own active estimate links, stored offer/attempt timestamps on spot_offered enquiries, shared phone/job claims and reminder-only activation; encrypted links POST through canonical save. Why: decouple email URL matching without weakening other guards.
- Incoming reset credentials bind Save to the verified user; old sessions never satisfy links. Office TEST handover (Deep's login; testRigor installer/electrician, decision 403) uses exact QA preflight and a private download of one-time set-password links; no link for the admin office account. Why: no cross-account access or public credential files.
- Staff labels/disclosure targets use pure `src/lib/portal-presentation.core.ts`, never workflow or eligibility decisions. Why: presentation must not duplicate domain rules.
- Office nav uses `src/config/office-nav.ts` (decision 218: Needs me · Enquiries · Jobs · Partners · Money · More); legacy routes redirect. Office screens read pure `office-needs`/`office-jobs`/`job-next-action`/`office-stage-cards`/`contact-history`/`office-filters`/`name-address-tidy` cores; Cancel = `cancelJobFully` (decision 227) everywhere, incl. email-change Apply; the Money card uses `jobMargin` and never records payments (decision 240). Why: one queue, one next action, intact bookmarks.
- REC and installer onboarding keep legacy step keys for history but show nine page groups (installer: `INSTALLER_VISIBLE_PAGES`); each group validates all members and persists its canonical anchor; installer contact details are asked once, signing authority only at signing. Why: old drafts resume safely without weakened gates.
- Trade screens (`/field`, `/field/offer|day|money|business|welcome`) read only through `trade-view.server.ts`, business-scoped; labels in pure `trade-view.core.ts`. Why: trades never see customer prices, margins or other partners.
- Installer tests use TEST accounts and restore snapshots; Closed lists use the exact live-TEST archive complement, Active unchanged. Why: isolation and bounded response headers.
- Office operations categories and compact job status reuse the operations read classifier and one shared Query cache; legacy preview remains direct-link. Why: unique counts and factual precedence must agree without navigation polling.
- Installer Add job shares CustomerFields and guarded import handlers; legacy bookmarks redirect there. Quote-removal events stay separate from measured facts; `intake-quote-details.core.ts` validates shared quote inputs. Why: one intake, no double counting.
